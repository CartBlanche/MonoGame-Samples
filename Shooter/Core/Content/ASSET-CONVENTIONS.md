# Shooter asset conventions (Unity FPS Microgame -> MonoGame 3.8.5 DesktopGL, HiDef)

Everything under `Textures/`, `Audio/`, `Fonts/`, `Models/` plus `Shooter.mgcb` and `AssetMap.json` is GENERATED by
`Tools/ContentGen/gen_content.py` from `Tools/UnityExtractor/out/asset-manifest.json` and the Unity `.meta` files:

    python3 -I Tools/ContentGen/gen_content.py          # from the Shooter folder; add --full-res to skip texture downscaling

Do not edit `Shooter.mgcb` by hand. Skinned rigs/animations (HoverBot, Turret, `@` clips) live in `Characters.mgcb`.
The static-model content processor is `Tools/Shooter.StaticPipeline` (net8.0, because the dotnet-mgcb 3.8.5 host runs on .NET 8);
`Shooter.csproj` builds it before mgcb runs, and `Shooter.mgcb` references `bin/Release/net8.0/Shooter.StaticPipeline.dll`.

`AssetMap.json`: `assets[<Unity asset path>]` (fonts: `font:<family>:<px>`) -> `{ name, type, ...metadata }`, plus `guidIndex[guid] -> path`.
`name` is the `ContentManager.Load<T>` name (no extension). Types: `Texture2D`, `Sprite` (loads as Texture2D), `SoundEffect`, `Song`, `SpriteFont`, `Model`.

## 1. Coordinate system and unit rules (verified, see section 6)

Unity: left-handed, Y up, +Z forward, 1 unit = 1 m. MonoGame: right-handed, Y up, -Z forward. We keep Y up and 1 unit = 1 m and
mirror the **Z axis** (Unity +Z forward becomes MonoGame -Z forward, +X stays right):

    F = diag(1, 1, -1)                                   // Unity world -> MonoGame world
    position   (x, y, z)        -> (x, y, -z)
    quaternion (x, y, z, w)     -> (-x, -y, z, w)        // F R F ; Unity Euler(0,90,0) maps +X -> -Z, so rotation SIGN is handled by this rule
    scale      (x, y, z)        -> (x, y, z)             // local scale is unchanged (F S F = S)
    local TRS of every node in a hierarchy is converted independently with the same rules (conjugation by F composes).

World matrix = `Matrix.CreateScale(s) * Matrix.CreateFromQuaternion(q') * Matrix.CreateTranslation(p')` per node, parent-multiplied as usual
(`child * parent` in XNA row-vector convention).

Cameras: Unity camera looks down +Z; after F it looks down -Z, which is MonoGame's `Matrix.CreateLookAt/CreatePerspective` default. Unity vertical FOV is
`Camera.fieldOfView` in degrees (use it directly); near/far unchanged.

## 2. Meshes (Models/, ModelProcessor = `StaticModelProcessor`)

Unity imports FBX/OBJ by mirroring X (right-handed file data -> left-handed Unity) and applies `globalScale * fileScale`.
Unity mesh vertex = `(-x_file, y_file, z_file) * scale` (verified on OBJWall_Door, FBX weapon pieces). Composing with F gives
`(-x, y, -z)` = **RotationY(180 deg)** of the file data. So the pipeline bakes, per model, into the VERTEX DATA (positions, normals, tangents):

* `RotationY=180` (== x->-x, z->-z) - this already IS "Unity mesh, converted to MonoGame space"; do **not** mirror again at runtime.
* `Scale = globalScale * (UnitScaleFactor/100 when useFileScale)` read from the `.meta` and the FBX header (1.0 for all models except `Mesh_Projectile` = 0.01).

Runtime rules for static models:

* **Ignore `ModelBone` transforms completely.** Assimp keeps node TRS (including Maya's `Lcl Scaling 0.01`) in the bones, but Unity's prefabs already carry the
  node TRS (e.g. `Primary_Weapon_Front_Piece_01` at local (-0.144, 0.329, -0.532) in `Weapon_Blaster.prefab`) and the mesh asset is raw geometry. Use
  `ModelMesh.MeshParts` vertex data with the transform from the scene JSON only.
* Match a Unity `MeshFilter.m_Mesh.name` to `ModelMesh.Name` (the FBX mesh-node / OBJ `o` name, e.g. `Primary_Weapon_Container_03`, `Wall_4m`).
* `ModelMeshPart.Tag` (string) = source material name (OBJ `usemtl` / FBX material). Unity `MeshRenderer.m_Materials[i]` = submesh i; match by
  **Tag name against the Unity material file name where the OBJ importer remapped it** (`AssetMap` -> `externalMaterialGuids`), otherwise by order.
  OPEN QUESTION: `OBJBasic_Floor` first-use order is (Floor_Grey, Floor_DarkGrey) but `Basic_Floor_Mesh.prefab` lists `[Floor_DarkGrey.mat, Floor_Grey.mat]`;
  `Wall_4m` first-use (Wall_Grey, Wall_DarkGrey) equals its prefab list. Unity's real submesh order for OBJ cannot be confirmed without Unity. Name matching is the
  safe default; compare against `Tools/UnityReference/*.png` screenshots for the floor.
* Vertex layout: `Position0 Vector3, Normal0 Vector3, TextureCoordinate0 Vector2, Tangent0 Vector3, Binormal0 Vector3` (stride 56, 16-bit indices). The part's `Effect` is a
  placeholder `BasicEffect` (no textures; the FBX/MTL texture paths are dropped because several are absolute paths on the artist's machine) - replace it with the PBR effect.
* **Winding**: MonoGame's OpenAssetImporter flips Assimp's triangle order so that the default `CullCounterClockwise` is correct. No extra winding handling
  (verified: every triangle's RH cross product points against the vertex normal). The Z-mirror in section 1 is a pure Y rotation for meshes and a
  reflection for transforms, so winding never needs to change. If you ever apply F to a mesh directly (you should not) you must swap winding.
* **UV**: pipeline applies `FlipUVs` (`v' = 1 - v_unity`). Unity's texture origin is bottom-left (v up), MonoGame's texture row 0 is the image TOP, so `Sample(u, v')` hits the same
  texel as Unity's `Sample(u, v)`. Textures are loaded unflipped. Do not flip again anywhere (UI sprites: Unity sprite rects are bottom-left based; MonoGame
  `SpriteBatch` rects are top-left based - flip Y there).
* **Tangent space** (verified numerically against per-triangle UV derivatives): `Tangent0 = dP/du`, `Binormal0 = dP/dv'` (v' is flipped, so it points toward image-bottom).
  Unity normal maps are OpenGL-style (green = +v = image up, `flipGreenChannel: 0`). Shader: `T = Tangent0; B = -Binormal0; N = Normal0; n = normalize(T*nx + B*ny + N*nz)` with
  `nx,ny,nz = tex.rgb*2-1` (the normal textures are plain RGB8, `Blaster_Normal`, `HealthPickup_Normal`, `ThickSmoke_N`; `ThickSmoke_N` also has an alpha channel).
* Mesh bounding data after the bake (MonoGame space, local, before the transform): `OBJWall_4m` x[-0.25,0.25] y[0,4] z[-3,0] (Unity: z[0,3]); `OBJBasic_Floor` x[0,3] y[-0.25,0.25] z[-3,0] etc.

## 3. Textures (Textures/<Area>/<name>.png -> Texture2D)

* Files are copied from `Assets/FPS/Art/Textures/<Area>/`; `.psd` (Falloff, Shadow), `.tga` (Symbol_*), 16-bit PNG (ThickSmoke_N) and the two backgrounds that are really JPEG data
  inside a `.png` name (Unity_skyboxBG01/02) are flattened to 8-bit PNG with ImageMagick (`convertedFrom` in AssetMap).
* Processor: `TextureProcessor`, `TextureFormat=Color`, **`ColorKeyEnabled=False`** (MonoGame's default is True and would punch out magenta pixels), **`PremultiplyAlpha=False`**
  (Unity blends with straight alpha, and the alpha of `*_MetallicSmooth` is smoothness; use `BlendState.NonPremultiplied` for sprites), `ResizeToPowerOfTwo=False`,
  `MakeSquare=False`, `GenerateMipmaps` = Unity's `enableMipMap` for non-sprites (all 3D/VFX textures: yes; UI sprites and the skybox: no).
* **Size**: like Unity's player build, non-UI textures are downscaled to the `DefaultTexturePlatform maxTextureSize` (512 for all but the skybox). 1024/2048 sources -> 512. UI sprites and the skybox keep their full
  resolution. `--full-res` disables this. Content size: 52 textures = 88 MB of .xnb (uncompressed RGBA8 + mips); 33 MB of that is the skybox.
* **Skybox**: `UnityTutorial_Skybox05_4k.png` is 4096x2048 equirectangular (lat-long, `_MAPPING_LATITUDE_LONGITUDE_LAYOUT`). It loads on HiDef (4096 is the HiDef maximum) as `SurfaceFormat.Color`,
  no mips (Unity `enableMipMap 0`), `filterMode 2` (trilinear), wrap repeat, 32 MB in memory/.xnb (a DXT1 build would be 4 MB; kept lossless on purpose).
  Skybox material (Skybox/Panoramic): `_Exposure 0.6`, `_Tint (1,1,1,0.5)`, `_Rotation 0`, `_ImageType 0` (360 deg), `_Layout 0`, `_MirrorOnBack 0`. Panoramic output = `tex.rgb * _Tint.rgb * unity_ColorSpaceDouble.rgb (about 4.59 in
  linear colour space) * _Exposure`. Lat-long lookup (Unity's `ToRadialCoords`): with `d` = view direction in UNITY space (`d = (x, y, -z)` of the MonoGame direction), `latitude = acos(d.y)`, `longitude = atan2(d.z, d.x)`,
  Unity uv = `(0.5 - longitude/(2 pi), 1 - latitude/pi)`; MonoGame texture coordinate (image top = 0) is therefore `u = 0.5 - longitude/(2 pi)`, `v' = latitude/pi`.
* **sRGB / linear colour space.** Unity runs in LINEAR colour space (sRGB textures decoded on sample, framebuffer encoded on write). What MonoGame 3.8.5 offers:
  `TextureProcessor` has **no sRGB output option** (`TextureProcessorOutputFormat` = Color, DxtCompressed, Compressed, Color16Bit, ETC/PVR/ASTC...; no `ColorSRgb`), but the framework has
  `SurfaceFormat.ColorSRgb` (+ `Dxt1/3/5SRgb`) and `GraphicsCapabilities.SupportsSRgb`. Tested on this machine (Apple M2, DesktopGL): `new Texture2D(gd, w, h, mipMap, SurfaceFormat.ColorSRgb)` works with mips, SetData(level) works,
  and sampling a texel of 128 yields 55 (= exact sRGB->linear) while a plain `Color` texture yields 128. **Decision**: the pipeline stores everything as plain `Color` (raw PNG bytes) and
  `AssetMap` carries `srgb` per texture; the runtime renders the 3D scene in LINEAR into an HDR-capable render target (`HalfVector4`/`Rgba1010102`), samples every texture with `srgb == true` through a
  `ColorSRgb` copy (create `Texture2D(gd, w, h, true, ColorSRgb)` and copy level by level with `GetData/SetData(level, ...)`; mips authored in gamma space by the pipeline are a small accepted error) or, as a fallback, decodes
  in the shader (`pow(c, 2.2)`), and a final full-screen pass applies exposure/tonemap and linear->sRGB (`pow(c, 1/2.2)`) into the (non-sRGB) back buffer. This avoids relying on `PreferredBackBufferFormat = ColorSRgb`
  (not verified here). UI sprites are drawn directly in gamma space (Unity UI in linear mode also blends in gamma-corrected look for sprites; keep SpriteBatch unconverted).
* `srgb` in `AssetMap` is Unity's *authored* flag. Note Unity marks the AO and MetallicSmooth maps `sRGBTexture: 1` too (only the normal maps and `Flare`/`Falloff` are 0). To reproduce Unity's picture exactly, decode those
  as sRGB as well; `role` = `albedo|emissive|data|normal|vfx|ui|skybox` lets the shader author decide. (The physically "correct" choice would be linear for `data`.)
* Sampler state from `AssetMap`: `wrapU/wrapV` (repeat|clamp), `filter` (point|bilinear|trilinear; trilinear/bilinear map to `SamplerState.LinearWrap/LinearClamp`, add `AnisotropicWrap` if wanted).
  `alphaIsTransparency` only means Unity dilates colour under transparent pixels (not reproduced).

## 4. Audio (Audio/... -> SoundEffect / Song)

* 21 clips. `Wind Ambience.mp3` (38.5 s music/ambience loop, 2D, loops via GameManager's AudioSource) -> **Song** (`Mp3Importer` + `SongProcessor`, `MediaPlayer.IsRepeating = true`).
  All others -> **SoundEffect** (`WavImporter`/`Mp3Importer` + `SoundEffectProcessor`, Quality=Best); the two mp3 SFX (`Turret_Alert` 1.27 s, `Damage_Tick2` 0.05 s) go through the bundled FFmpeg, no manual conversion needed.
  Spaces are replaced by `_` in the content name (`Audio/Music/Wind_Ambience`).
* Metadata in `AssetMap.assets[...].playback`: `loop`, `spatialBlend` (0 = 2D, 1 = 3D), `minDistance`/`maxDistance`, `volume`. Known from AudioSource components: `Hoverbot_Movement` loop 3D (1..20 m, vol .75), `Jetpack_Use` loop 2D,
  explosions `Turret_Death`/`Hoverbot_Death` spatialBlend .8 (1..500). The remaining clips are triggered from scripts; defaults: enemy sounds 3D-ish (blend .5, 1..20 m, linear rolloff), player/UI/weapon 2D. Unity import settings
  recorded: `forceToMono`, `unity3D`, `normalize` (Unity normalizes on import: all true).
  Use `SoundEffectInstance` with `AudioEmitter/AudioListener` for 3D (remember Z flip when feeding positions).

## 5. Fonts (Fonts/<Family>_<px>.spritefont -> SpriteFont)

TextMeshPro SDF assets reference: `LiberationSans SDF` (+ `LiberationSans SDF - Fallback`, same TTF), `Roboto-Black SDF`, `Roboto-Regular SDF`. TTFs: `LiberationSans.ttf` (SIL OFL 1.1, from `Assets/TextMesh Pro/Fonts`, license text copied
as `Fonts/LiberationSans.LICENSE.txt`) and Roboto Black/Regular (Apache 2.0; the TTFs are NOT in `Assets/` - only pre-baked SDF atlases are - so they are taken from the identical family in
`Library/PackageCache/com.unity.searcher@.../FlatSkin/Font/`; license `Fonts/Roboto-*.LICENSE.txt` = `ApacheLicense2.0.txt`). Characters: U+0020-00FF, en/em dash, bullet. MonoGame `Size` is in pixels at 72 dpi (== px of the Unity canvas units).
Sizes generated, from the TMP `m_fontSize` / auto-size maximums in the four scenes + prefabs:

* LiberationSans: 10, 14, 16, 26 (14 is the default body size: 24 uses)
* Roboto-Black: 7, 9, 10, 18, 22, 24, 25, 35 (34.92), 45, 72 (25 and 45 are auto-sized texts with min 12, max 25/45: scale a larger font down)
* Roboto-Regular: 12

Not reproduced: bold/italic flags (`m_fontStyle 1` = Bold on a few labels; `16` = UpperCase transform: `ToUpperInvariant()` the string), SDF outlines/shadows, rich-text. Read each canvas's CanvasScaler reference resolution from the extractor JSON before laying out text.

## 6. Verification performed (throwaway console in the session scratchpad, not committed)

* Loaded all of: skybox, normal/AO/metallic/Symbol alpha textures, Song + 3 SoundEffects, 3 fonts, all 12 models on DesktopGL HiDef (Apple M2): OK. `ColorSRgb` texture test: OK (128 -> 55).
* **Handedness / unit proof on an asymmetric mesh**: `OBJWall_Door` (raw x[-3,0], z[-0.25,0.25]). The `Room_Medium` prefab places it at (0,0,15) with rotation (0,0.7071,0,0.7071) and the neighbouring
  `Wall_4m`s cover z [9,12] and [15,18], leaving a [12,15] gap. Applying the section-1 rules to the baked vertices yields Unity-space bbox x[-0.25,0.25] z[12.00,15.00] (fills the gap exactly);
  the identity-rotation door at (12,0,27) yields x[12,15] z[26.75,27.25] (also fills its gap). Without the X mirror they would land on [15,18] and [9,12] (inside the walls).
* FBX weapon: Unity `Primary_Weapon_Front_Piece_01` local position x = -0.1444 while the raw FBX node has +0.1444 (X mirrored); `Weapon_Primary` child is rotated 180 deg about Y with scale .45 and its
  muzzle `GunMuzzle` z = 0.456 matches the mesh front tip (z -0.6545 * 0.45 + 0.178 -> 0.47 after the 180 deg turn).
* Floor tiling: `Floor_6x6` places `Basic_Floor` at x,z in {0,3,6}; with the mirror the tile covers [p, p+3] (raw [-3,0]) and exactly fills the 27x27 `Room_Medium` bounded by walls at 0 and 27.
* Triangle normals vs index order: all CW-in-RH (MonoGame front-face convention) for every part tested. Tangent/Binormal vs UV derivatives: 100% agreement (Tangent = dP/du, Binormal = dP/dv').
* Model counts after processing (verts / tris): Weapon_Primary 2605/1882 (7 meshes, 11 parts), Projectile 60/20, Health_Pickup 82/112, ExplosionDisk 132/192 (flat disk, r = 0.981), Sun 24/22 (r = 100, at z = -1219; prefab scale .0266,.0266,.163),
  OBJWall_4m 96/48, OBJWall_Door 116/96, OBJBasic_Floor 96/48, OBJRamp_8m 24/12, OBJDun_BigDoor 160/140, Diamond_Sign 27/24, Triangle_Sign 25/18. Note the baked `Mesh_Sun`/`ExplosionDisk` sizes are the raw Unity sizes (Unity ignores the 0.01 node scale).
